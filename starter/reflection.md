# Project Reflection

I selected Amazon Nova 2 Lite (`global.amazon.nova-2-lite-v1:0`) as a cost-conscious model for a customer-support workflow that needs tool selection and concise answers. The architecture separates information retrieval from transactions: the Bedrock Knowledge Base Retrieve API supplies product and policy facts, while order and refund operations are exposed as remote tools through the MCP Gateway. The browser and loyalty calculator remain local agent tools.

A significant challenge was the VocLabs IAM restriction around AgentCore Memory. The lab policy `voc-cancel-cred` blocked `bedrock-agentcore:CreateMemory` in the console; an SDK `GetMemory` call also returned an explicit access denial, and a later strategy lookup returned an empty list. After the existing Memory resource became available for updates, I added and activated the semantic and user-preference strategies. The deployed Test 4 then saved Jane's facts and preference under `CUST-123` in one session and recalled them in a distinct session. Both strategy namespaces returned extracted records; the live commands, responses, event IDs, and retrieval evidence are saved in `test_outputs/Test 4 - Cross-session memory verification.txt`.

For production, I would assign separate least-privilege IAM roles to the runtime and tool targets, replace the sandbox Gateway's unsigned authorizer, and store secrets in a managed secret store with rotation. I would cache only stable catalog and policy retrievals, never order or refund state, and key cached data by query and knowledge-base version. MCP startup and tool calls should have explicit timeouts and structured error handling: an asynchronous `TaskGroup` can wrap a lower-level transport failure, so logs should retain the underlying exception and the request should fall back safely when possible. Tracing, latency metrics, audit logs, and automated schema validation would make failures diagnosable.

The AgentCore runtime was deployed and verified on 2026-10-05. The initial cloud invocation returned a customer-support response without a runtime error. Deployed order tracking, refund processing, Knowledge Base retrieval, and loyalty calculation also returned the expected results. The deployed browser request reached the agent, but the browser tool reported a Playwright driver permission problem. After correcting the loyalty tool to parse and validate the Code Interpreter's structured stdout, I redeployed the runtime and verified the 1,500-point Gold calculation both with mocked success/error streams and through the live runtime. Command and response evidence is saved in [the initial runtime invocation](./test_outputs/AgentCore%20runtime%20invocation%20-%20hello.txt), [the functional scenario results](./test_outputs/AgentCore%20runtime%20functional%20scenarios.txt), and [the successful memory test](./test_outputs/Test%204%20-%20Cross-session%20memory%20verification.txt).
